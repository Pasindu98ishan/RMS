# Data model — Phase 1

Logical model the backend implements with Flyway. Later phases add their tables here before they are built.

## Conventions (all tables)
- `id uuid PK` (generated by the app), `branch_id uuid NOT NULL` on business tables.
- `created_at`, `updated_at timestamptz`, `created_by`, `updated_by uuid` (user).
- `version int` for optimistic locking on editable rows.
- Money `numeric(12,2)`; rates `numeric(5,2)` (percent); quantities `numeric(10,3)`.
- Soft delete via `active boolean` for master data. Transactions (orders, bills, payments) are **never deleted**.
- Enums stored as `varchar` with a CHECK constraint.

## Entity overview

```
branch ─┬─ terminal
        ├─ app_user ─── user_role ─── role ─── role_permission ─── permission
        ├─ setting (key/value) · service_charge_rule · delivery_area · reason
        ├─ category ─── menu_item ─┬─ menu_item_price (price_list: LOCAL|FOREIGN)
        │                          ├─ menu_item_modifier_group ─── modifier_group ─── modifier_option
        │                          └─ kitchen_station
        ├─ dining_table · ordering_point
        ├─ customer · rider
        ├─ shift ─┬─ petty_cash_entry
        │         └─ shift_cash_count
        ├─ business_day
        ├─ order ─┬─ order_line ─── order_line_modifier
        │         ├─ kot ─── kot_line
        │         ├─ discount
        │         ├─ bill ─── payment
        │         └─ refund
        ├─ number_counter
        ├─ print_job
        ├─ kds_heartbeat (or in-memory + station_status)
        ├─ notification
        └─ audit_log
```

## Tables

### Access
| Table | Key columns |
|---|---|
| `app_user` | username (unique), password_hash, pin_hash, full_name, phone, active, locked_until, failed_attempts, pin_failed_attempts, pin_locked_until, employee_id (nullable, Phase 5) |
| `role` | name, system (bool — seeded roles can't be deleted) |
| `permission` | code (e.g. `ORDER_CREATE`), description, module |
| `user_role`, `role_permission` | join tables |
| `terminal` | name, type (`CASHIER_POS`,`RECEPTION_POS`,`KITCHEN`,`ADMIN`,`DISPLAY`), kitchen_station_id (for KITCHEN), ordering_point_id, device_token_hash, active |
| `refresh_token` | user_id, terminal_id (null for a personal session, ADR-008), session_id, token_hash, expires_at, revoked_at |

### Settings
| Table | Key columns |
|---|---|
| `setting` | key, value (jsonb) — restaurant details, business_day_start, tax_enabled=false, tax_rate=0, idle timeouts, `menu` (resetAvailabilityDaily), `availability_reset` (last daily sold-out reset marker) |
| `service_charge_rule` | order_type, rate |
| `delivery_area` | name, fee, active |
| `reason` | category (`CANCEL`,`VOID`,`REFUND`,`PETTY_CASH`,`DISCOUNT_OTHER`), text, active |
| `discount_rule` | type (`STAFF`,`GOVERNMENT`,`OWNER`,`OTHER`), name, mode (`PERCENT`,`AMOUNT`), rate, max_rate, cashier_limit, approval_level (`NONE`,`MANAGER`,`OWNER`), monthly_limit_per_staff, active |

### Menu and floor

|---|---|

### Kitchen

### Platform
| Table | Key columns |
|---|---|
| `print_job` | terminal_id, type (`RECEIPT`,`X_REPORT`,`Z_REPORT`,`SHIFT_CLOSE`), payload (jsonb), status (`QUEUED`,`SENT`,`PRINTED`,`FAILED`), attempts, error |
| `notification` | user_id / role, type, title, body, read_at |

| `idempotency_record` | key, endpoint, user_id, response_hash, created_at (24 h retention) |

## Key indexes and constraints
- `bill (branch_id, bill_no)` unique; `order (business_day_id, order_no)` unique.
- `menu_item_price (menu_item_id, price_list)` unique.
- Partial unique: one `OPEN` shift per (user, terminal); one `OPEN` business_day per branch.
- `order (status)` where status not in closed states — for live order lists.
- `audit_log (at)`, `(entity_type, entity_id)`.
- Report queries: `payment (shift_id)`, `order (business_day_id, order_type)`, `order_line (menu_item_id)`.
