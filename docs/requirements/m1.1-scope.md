# M1.1 scope — Catalog & floor

Requirement IDs and acceptance criteria are in [`phase-1-requirements.md`](phase-1-requirements.md) §2–§3. This note fixes the exact scope of milestone M1.1, the import format, and the sample data used for testing. Written 2026-11-21.

## In scope

| Area | Requirement IDs | What is built |
|---|---|---|
| Kitchen stations | P1-MENU-07, P1-SET-05 | 3 stations seeded (names editable), target prep time per station, active flag. List endpoint so terminal setup can pick a station. |
| Ordering points | P1-FLOOR-02 | 2 seeded: Cashier, Reception. List endpoint so terminal setup can pick one. |
| Categories | P1-MENU-01 | CRUD, display order, active flag. |
| Menu items | P1-MENU-02, 05, 06 | CRUD with code (unique), name, category, **exactly one** kitchen station, local price, foreign price (optional), active, available (sold out today). Price changes audit-logged. |
| Modifiers | P1-MENU-03 | Modifier groups (required, min/max select) with options (price delta); attach groups to items. |
| Price lists | P1-MENU-04 | LOCAL and FOREIGN price per item. (Choosing the list per order is M1.2.) |
| Tables and floor plan | P1-FLOOR-01 | Tables (number, section, seats), drag-to-arrange floor plan editor, active flag. |
| Delivery areas | P1-SET-07 | Areas with a fee. (Used by delivery orders in M1.2.) |
| Reasons | P1-SET-08 | Editable reason lists: CANCEL, VOID, REFUND, PETTY_CASH, DISCOUNT_OTHER. Seeded with sensible defaults. |
| Import | P1-IMP-01 | Spreadsheet import of categories, menu items (with prices and station), modifier groups, tables. |
| M1.0 leftovers | P1-AUTH-04 | Terminal registration can now choose a kitchen station and an ordering point; KITCHEN terminals require a station. |

## Out of scope for M1.1
Orders, KOTs, the kitchen screen (M1.2–M1.3), discount rules (M1.4), stock/recipes (Phase 2), per-order price list choice (M1.2).

## Permissions (from roles-permissions.md)
`MENU_MANAGE` (items, prices, modifiers, categories, stations), `MENU_AVAILABILITY` (sold-out toggle: Owner, Manager, Cashier), `FLOOR_MANAGE` (tables, floor plan: Owner, Manager), `DATA_IMPORT` (Owner), `SETTINGS_MANAGE` (delivery areas, reasons). Read access for lookups used by POS screens: add narrow `*/options`-style read endpoints with the permission that screen needs, as done for roles/users.

## Decisions made for M1.1 (change by telling the lead)
1. **Item deletion:** items are never deleted, only deactivated (past orders will refer to them). Same for categories, tables, stations, areas.
2. **Item code** is unique per branch, 1–20 chars, `A-Z 0-9 -`. Used for POS search.
3. **Foreign price** is optional. An item without a foreign price cannot be added to a FOREIGN-list order (enforced in M1.2).
4. **Station is required** on every item. An item cannot be saved without one.
5. **Sold out** ("available" = false) resets automatically at the start of each business day, so a forgotten toggle can't hide an item forever. (Setting: on by default.)
6. **Deactivating a category** hides its items from the POS; it does not change the items' own flags.
7. **Floor plan** stores x/y per table in a 1000×700 logical grid; the POS floor view scales it.
8. **Import is all-or-nothing** (P1-IMP-01). Re-importing an existing code **updates** that item (matched by code); it never creates duplicates.

## Import format (CSV or XLSX)
One file per import type; the template for each can be downloaded from the Import screen. First row is the header. Text is UTF-8; money has 2 decimals, no thousands separators.

**categories** — `name`, `sort_order`
**menu_items** — `code`, `name`, `category`, `station` (station number 1–3), `local_price`, `foreign_price` (optional), `modifier_groups` (optional, names separated by `|`), `active` (Y/N, default Y)
**modifier_groups** — `group`, `required` (Y/N), `min_select`, `max_select`, `option`, `price_delta` (one row per option; rows with the same `group` belong together)
**tables** — `number`, `section`, `seats`

Validation (all rows checked first; any error → nothing imported):
- unknown category / station / modifier group name
- duplicate code inside the file
- price missing, negative or not a number; `max_select < min_select`
- row and column reported for every error ("menu_items row 14, local_price: 'abc' is not a number")

Response: a validation report (`ok` flag, counts created / updated / unchanged, list of errors).

## Sample data for testing (dev seeder, profile `dev` only)
- Stations: Kitchen 1 "Rice & Curry", Kitchen 2 "Grill", Kitchen 3 "Juice & Dessert", target 15 / 20 / 8 min.
- 6 categories: Rice & Curry, Short Eats, Grill, Beverages, Desserts, Liquor.
- About 40 items across the three stations with local prices; ~25 also have a foreign price.
- 3 modifier groups: Spice level (required, pick 1), Extras (optional, pick up to 3, with price), Size (required, pick 1).
- 12 tables in two sections (Indoor 1–8, Garden G1–G4).
- 3 delivery areas with fees (Netolpitiya 150, Nearby 300, Far 500).
- Default reasons for each reason list.
- Idempotent: running twice creates nothing new.

## Definition of done (M1.1)
- All M1.1 requirement IDs have passing tests (backend integration, frontend unit, E2E).
- Terminal setup can register a KITCHEN terminal with a station against the real backend.
- Admin can build a menu by hand and by import, arrange the floor plan, and mark items sold out.
- Roles checked: cashier can toggle availability but not edit items; kitchen/rider/inventory/HR see none of the menu admin screens.
- No open Critical/High bugs; `docs/qa/phase-1/signoff.md` updated.
